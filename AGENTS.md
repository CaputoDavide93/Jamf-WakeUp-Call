# Agent instructions

Jamf WakeUp Call is a small Python CLI that asks Jamf Pro to redeploy the management framework on Macs chosen by dynamic group, serial number or serial file. The repo is superseded by [Jamf-Snipe-IT-Suite](https://github.com/CaputoDavide93/Jamf-Snipe-IT-Suite) and receives fixes only.

## Commands

```bash
make venv     # .venv with runtime and test dependencies
make check    # pytest, diagram freshness, icon freshness (what CI runs)
make diagram  # redraw docs/assets/*.svg after editing tools/gen_diagram.py
python3 -m src.main --group-id 42 --dry-run   # run the CLI from the repo root
```

Run `make check` before and after every change. Anything green before stays green.

## Layout

| Path | Holds |
|---|---|
| `src/main.py` | CLI and orchestration |
| `src/jamf_client.py` | Jamf Pro API client, token handling, retries |
| `src/config.py` | Configuration read from the environment |
| `tests/` | pytest: config placeholders, record shape, diagrams, docs links |
| `tools/gen_diagram.py` | Draws `docs/assets/*.svg` (`--check` fails when they are stale) |
| `tools/brand/` | Icon and social preview generator, icon freshness check |
| `tools/screenshots/` | Local mock of Jamf Pro and the script behind `make screenshots` |
| `docs/` | Setup, usage, configuration, how it works, troubleshooting, FAQ (index in `docs/README.md`) |

## Conventions

- Python `snake_case`, directories `lowercase-kebab`, shell scripts `kebab-case.sh`, docs `docs/lowercase-kebab.md`.
- Root holds only README, LICENSE, SECURITY, CONTRIBUTING, CHANGELOG, AGENTS (`.md`) plus config files.
- Commits are conventional (`fix:`, `feat:`, `docs:`, `refactor:`, `ci:`, `chore:`) and authored by the repo owner. No co-author trailers, session ids or "generated by" lines in commits, PRs, issues or comments.
- Documentation must be true of the code: every command, flag and badge is verified, and counts are not typed by hand.
- Screenshots come from `make screenshots` against the mock; retake them when CLI output changes.
- README ends with the author footer line and nothing after it.

## Do not change

Runtime identifiers are public API for people who run the tool: environment variable names (`JAMF_PRO_URL`, `JAMF_PRO_API_TOKEN`, `JAMF_PRO_USERNAME`, `JAMF_PRO_PASSWORD`, `JAMF_DYNAMIC_GROUP_ID`, `LOG_LEVEL`, `LOG_FILE`, `API_TIMEOUT`), CLI flags, the `python3 -m src.main` entry point and the repo URL. Every variable the code reads must stay in `.env.example`.

## Secrets and demo data

Never commit secrets, keys, tokens, IP addresses, private hostnames or personal e-mail addresses. Vulnerabilities are reported through GitHub Security Advisories (see `SECURITY.md`). The repo is public: use demo data only (`example.com` hosts, made-up serials such as `DEMO0000101`), and no real tenant, device, user or employer names.

Anything that needs a real Jamf Pro tenant is unverified unless it was run against one; say so in the docs.
